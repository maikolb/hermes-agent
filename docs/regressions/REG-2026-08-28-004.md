# REG-2026-08-28-004 — FNAT bubble showed raw log dialect instead of the principal's surface

## Symptom
On 2026-08-28 ~01:37 (DOVTest, task `t_b2214937` run 13), the FNAT focus
bubble rendered raw worker-log lines — `┊ Tool: todo(planning 8 task(s))`
followed by complete result JSON (`todo ok 0.1s: {"todos": [...]}`) — while
the principal's chat surface for the same kind of activity is semantic
(`📚 Reading skill leadsmais-project`, `💻 terminal` + fenced command).
Operator regression report with side-by-side screenshots.

## Why it regressed
The rich rendering the operator remembered was never a FNAT feature: it was
in-process workers' tool events flowing through the principal turn's own
`tool_progress_callback` pipeline (gateway/run.py → agent/display.py), whose
bubbles are deleted by `display.cleanup_progress` when the turn ends ("the
message died afterwards"). When worker display moved to the persistent FNAT
bubble fed from worker logs (worker visibility + Vigília requirement), the
projection `_render_kanban_worker_focus_output` was born as a passive line
filter (commit d1e3fbb8a2, 25/08): it passed log dialect through verbatim,
so persistence was gained and rendering quality silently lost.

## Fix
`_render_kanban_worker_focus_output` now parses all three worker log
dialects (in-process tee, live-transcript fallback, dispatcher CLI stdout)
back to (tool, args) and re-renders each line with the same emoji +
friendly-verb tables the principal uses (`agent/display.py`). Success
results are dropped exactly like the principal's surface; errors keep a
short extracted message; reasoning renders as a `💭` line. PR #41
(aa12fbb0bc).

## Guard
`tests/tools/test_inprocess_board_log.py::test_tee_writes_native_dialect`
asserts the bubble output contains the friendly-verb rendering and **no**
`┊` dialect marker; `tests/gateway/test_worker_closeout_traces.py` gained
two tests pinning the three dialects, the success-result drop, and the
error-message extraction. Any return to raw passthrough fails those.
