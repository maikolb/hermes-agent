# REG-2026-08-24-010 — terminal imports the local backend before the Windows zero-UI boundary

## Status

- Root cause confirmed; corrected and reproduced locally; full candidate and
  target validation pending.

## Reproducible scenario

The focused Windows matrix failed all three terminal-boundary tests because
`tools.terminal_tool` did not expose or execute
`_install_windows_terminal_zero_ui_boundary()`:

```text
.venv\Scripts\python.exe -m pytest -q tests/tools/test_terminal_zero_ui_boundary.py
```

Pre-correction result: 3 failures with `AttributeError`; the module imported
`LocalEnvironment` directly.

## Root cause with evidence

The preserved local-runtime commit `8b76dee159` carries the three boundary
tests but not the corresponding production hunk.  The earlier source lineage
`2173defe1c` contains both the tests and the production boundary, which must run
before importing `tools.environments.local`.  Consolidating the rebased
test-only commit without its ancestor silently separated the prevention test
from the implementation.

## Correction

Install and verify the process-wide Windows broker immediately before importing
`LocalEnvironment`; fail closed if the broker is not active.  Non-Windows
imports remain a no-op.

## Prevention gate

`tests/tools/test_terminal_zero_ui_boundary.py` proves install, fail-closed and
non-Windows behavior.  The broader Windows broker/process/static-footgun matrix
and external `VisibleWindows=0` verifier remain required before release.
