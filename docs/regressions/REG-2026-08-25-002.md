# REG-2026-08-25-002 — NF durable final suppressed by stale cached-agent route

## Incident

The VPS NF received `mostra o kanban`, generated the correct answer, then suppressed the final because its checkpoint recorded an empty Telegram `chat_id` while delivery used the real group route.

## Root Cause

Fresh agents receive route identity in their constructor, but reused cached agents only refreshed callbacks and model configuration per message. A stale/empty route therefore reached checkpoint creation and was correctly rejected by the fail-closed delivery fence.

Profile display settings had also drifted: Telegram's implicit tool-progress default is off, and several profiles explicitly disabled reasoning/tool activity or used the invalid background mode `errors`.

## Prevention

- Refresh platform, chat, thread, user, and gateway-session identity on every message before the turn starts.
- Regression-test a reused cached agent whose prior route is empty.
- Make reasoning/skill/tool/activity visibility explicit for every configured chat platform.
- Preserve and assert NF/PF worker-parallelism and focus-handoff keys during configuration repair.
