# REG-2026-08-25-003 - NF worker focus showed metadata but no worker output

## Incident

On 2026-08-25 at 22:17 UTC, the NF Telegram topic displayed `Now following worker` for task `t_c3923c5d` run 6 after the principal turn ended, but showed no activity tag, tools, or reasoning from that worker.

The worker's canonical task log grew to 10,983 bytes by 22:25:58 UTC and contained many tool-progress lines plus a `Reasoning` block. The worker produced the expected visible signals; the gateway never consumed them.

## Root Cause

`kanban.worker_focus_handoff` was implemented as a local counter and static task-metadata message. `_kanban_refresh_worker_focus()` selected a running task and sent or edited `Now following worker`, but did not call the existing `read_worker_log()` accessor or project any worker output into the topic. The focused tests encoded only the static-message behavior.

## Prevention

- Treat worker focus as an observable-output handoff, not only a task-selection notice.
- Read only a bounded tail through the canonical per-board worker-log accessor.
- Isolate the latest CLI attempt so retries do not replay historical output.
- Force-redact content before it can leave the gateway and keep one edited message per destination.
- Regression-test configured activity text, tools, reasoning, retry isolation, bounds, redaction, and fail-soft log reads.
