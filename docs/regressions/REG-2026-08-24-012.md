# REG-2026-08-24-012 — archiving a running task orphans its worker

## Status

- Root cause confirmed; correction and post-fix validation pending.

## Reproducible scenario

1. Create and claim a task with `status=running`, an active claim and a worker
   PID.
2. Archive it through the domain API or dashboard bulk/single archive path.
3. Observe that the database clears `worker_pid` and the claim and ends the run,
   but no worker termination is attempted.

The hermetic repro used a termination spy and produced an archived task with a
null PID and `termination_calls=[]`.

## Root cause with evidence

`archive_task()` performed the state transition and workspace cleanup but did
not snapshot the live worker identity before clearing it, nor call
`_terminate_reclaimed_worker()` after the transaction.  For a foreign or
unverified worktree, cleanup correctly preserves the checkout, leaving the
now-untracked process free to continue mutating it.

## Required correction

Capture the exact PID/claim/process-start identity inside the archive
transaction, persist the archive/audit trail, and terminate that captured
worker after commit.  Failure to terminate must remain visible and
reconcilable; it must never authorize worktree removal.

## Prevention gate

Cover direct, dashboard single and dashboard bulk archive of running tasks,
including a termination failure/restart-reconciliation case.  Assert the
worker is targeted post-commit while unverified/foreign checkout contents are
preserved.
