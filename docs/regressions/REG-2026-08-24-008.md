# REG-2026-08-24-008 — Windows zero-UI broker depends on import order

## Status

- Validated-local; candidate merge and target acceptance pending.
- The focused import-order reproduction, canonical delivery matrix and 20
  fresh-process crash/recovery repetitions are green.

## Reproducible scenario and observed evidence

1. Start a fresh pytest process with only
   `test_process_death_after_claim_before_send_remains_recoverable` selected.
2. The autouse live-system guard installs a policy subclass whose constructor
   is `Popen(cmd, *args, **kwargs)`.
3. A later fixture import activates the Windows zero-UI broker. At import time,
   the broker captures that policy subclass as `_original_popen`.
4. Before correction, `inspect.signature(_original_popen).bind(...)` produced
   `{"cmd": argv, "kwargs": {...}}`, but `WindowsHiddenPopen.__init__`
   unconditionally read `params["args"]`.
5. The first child process failed before launch with
   `KeyError: 'args'` at `hermes_cli/windows_process_broker.py`.

The canonical multi-file matrix initially hid the defect because another test
module imported the broker during collection, before the autouse policy wrapper
was installed. The same boundary therefore passed or failed according to import
order.

## Root cause

- The broker assumed every Popen-compatible policy wrapper preserved the
  stdlib constructor parameter name `args`.
- It used the wrapper's generic signature to normalize named Popen options,
  even though `cmd, *args, **kwargs` does not expose those option names.
- The existing full matrix did not include an isolated first-import proof, so
  prior module imports masked the invalid assumption.

## Correction

- Resolve the first concrete constructor signature in the captured wrapper's
  MRO that exposes the public positional `args` parameter.
- Keep the captured policy wrapper itself as `_original_popen` and as the
  executor; only call normalization uses the concrete base signature. The fix
  therefore does not bypass the live-system guard or weaken zero-UI policy.
- Close the test-only coroutine passed to a mocked `asyncio.create_task`, so
  the validation gate has no delayed `AsyncMock` warning attributed to an
  unrelated test.
