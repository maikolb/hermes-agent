# REG-2026-08-24-002 — Windows PTY reports false EOF success

## Status

- `validated-local`; candidate merge and target acceptance pending.

## Reproducible scenario

1. Start a Windows PTY child that blocks on `sys.stdin.read()`.
2. Write input through `ProcessRegistry.submit_stdin()`.
3. Call `ProcessRegistry.close_stdin()`.
4. The method returns `{"status":"ok","message":"EOF sent"}`, but the child
   remains blocked and never exits.

## Root cause and evidence

- The Windows backend is `pywinpty`/ConPTY.
- `PtyProcess.sendeof()` writes Ctrl-D; it does not close the ConPTY input
  pipe. A child performing an EOF-driven read therefore receives no real
  half-close.
- The existing end-to-end test was inherited from the POSIX PTY contract and
  ran without an OS marker. It proved the failure on Windows but could not be
  satisfied by the backend implementation.
- Calling `PtyProcess.close()` is not equivalent: it terminates the child and
  would violate the contract “close stdin without killing the process”.

## Correction

- `close_stdin()` now fails closed for a Windows PTY with an explicit
  unsupported-backend error; it never claims EOF success and never calls
  `close()` or `sendeof()`.
- The existing EOF-driven process test is POSIX-only.
- A Windows-only regression test proves the explicit error and absence of
  destructive PTY calls.
- Adjacent process tests were isolated by native OS branch so no unit test can
  accidentally invoke a real PTY or `taskkill` for a fictitious PID.

## Prevention and validation

- `tests/tools/test_process_registry.py::TestStdinHelpers::test_close_stdin_windows_pty_fails_closed`
- `tests/tools/test_process_registry.py::TestStdinHelpers::test_close_stdin_allows_eof_driven_process_to_finish`
- Validation command:
  `.venv\Scripts\python.exe -m pytest -q tests/tools/test_process_registry.py tests/tools/test_code_execution.py`
- Candidate evidence: `90 passed, 48 skipped, 5 subtests passed`.
- A future real Windows half-close requires a backend primitive that releases
  only the ConPTY input pipe; until then this operation remains intentionally
  unsupported rather than falsely successful.
