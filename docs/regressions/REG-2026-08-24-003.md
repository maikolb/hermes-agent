# REG-2026-08-24-003 — Archived Kanban subscription is never removed

## Status

- `validated-local`; candidate merge and target acceptance pending.

## Reproducible scenario

1. A task retains its notification subscription after reversible `done`.
2. The task is later archived.
3. The notifier claims the `archived` event but produces no delivery row.
4. The cursor/cleanup branch that removes the subscription never runs, leaving
   an orphan subscription indefinitely.

## Root cause

The merged notifier combines two valid contracts:

- chat is state convergence, never event-log replay;
- archive is silent but irreversibly ends notification ownership.

`archived` belonged to the claimed focus event set but not the visible notify
set. An early `continue` therefore removed it before the silent cleanup path.

## Correction and prevention

- Treat `archived` as a silent control delivery when no visible notification
  exists, so cursor advancement and unsubscribe run.
- If `completed` and `archived` share one claimed range, deliver the completion
  once, then use current task status to unsubscribe. Archive itself remains
  silent.
- Preserve `material_events[-1:]` convergence for visible notification events.
