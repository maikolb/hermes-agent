# REG-2026-09-02-001: Hermes continued above threshold after compaction failure

## Feedback

Maikol reported a Hermes turn that ran for 18 minutes, reached iteration 11 of 200, timed out its compression stream after 300 seconds, announced that context was still above threshold during a cooldown, and continued executing tools.

## Incident evidence

- Screenshot: `C:\Users\maiko\AppData\Local\Temp\codex-clipboard-bfd7c908-761a-480c-9f89-96b6e1ae6eb5.png`.
- Runtime log: `C:\Users\maiko\AppData\Local\hermes\logs\gateway-hidden-launch.log`.
- The log records an estimated request above the 231,200-token threshold, a 300-second Codex auxiliary timeout, unavailable fallbacks, then continuation at approximately 266,692 tokens while the same-session cooldown had 59 seconds remaining.
- Subsequent work in the same turn included tool waits of approximately 121 and 303 seconds.

## Reproduction

Drive `AIAgent.run_conversation` with:

1. compression enabled;
2. an assembled request above `ContextCompressor.threshold_tokens`;
3. `get_active_compression_failure_cooldown()` returning an active cooldown;
4. `should_compress_info()` returning `False` plus the cooldown reason.

Before the repair, the pre-provider branch emitted a warning and still called the model client. The regression fixture fails on `client.chat.completions.create.assert_not_called()` against the pre-repair behavior.

## Root cause

The overflow guard was advisory. Both the turn-start and pre-provider paths warned when compression was blocked above threshold, but the pre-provider path had no state transition or return. The oversized request therefore crossed the provider boundary and the tool loop remained eligible to continue.

## Prevention

At the existing pre-provider pressure boundary:

- keep below-threshold requests unchanged;
- when the request is above threshold and compression explicitly reports a block reason, refund the unmade model iteration;
- persist the original transcript;
- transition the existing turn checkpoint to `compaction_deferred` with `run_manual_compression_then_resume_current_turn`;
- return the existing soft `compression_deferred` result so the gateway preserves the session and cannot auto-reset it as exhausted;
- make zero provider calls.

The repair does not change the threshold, compression timeout, model, provider, summary prompt, `abort_on_summary_failure`, protected tail, memory lifecycle, or AOF.
