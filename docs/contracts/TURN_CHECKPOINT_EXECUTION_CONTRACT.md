## Root-Cause Hypothesis
The transcript and the executable turn state have different authorities. Compaction persists the transcript but not the control-plane state that interprets it. After compaction/restart, the model reconstructs progress from a lossy summary and tail messages, so continuity is probabilistic. The fix point is a profile-scoped write-ahead checkpoint journal captured at safe loop transitions and validated before transcript replacement; resume consumes that journal before further model/tool action.

## Structured Authority
Checkpoint schema version 1 must include:
- profile/session/turn identity and monotonic revision;
- exact active-user content hash plus redacted literal content;
- transcript before/after hashes and compaction state (`captured`, `prepared`, `committed`, `conflict`);
- runtime phase and explicit next action;
- pending tool fingerprint/status and accumulated uncertain outcomes;
- pending deliverable hash/redacted content and verification state;
- changed paths/artifacts/blockers;
- delivery obligation reference/status when available;
- payload checksum, timestamps, and atomic-write provenance.

## Transaction and Resume Rules
1. Persist and read-validate `captured` before summary generation.
2. Persist and read-validate `prepared` with both transcript hashes before active transcript replacement.
3. Replace/archive the transcript through the existing canonical session transaction.
4. Persist `committed` only after read-back matches the after hash.
5. On restart, reconcile a prepared journal against the live transcript: before-hash means swap did not occur; after-hash promotes commit; any third hash is `conflict` and fails closed.
6. A checkpoint write/validation failure aborts compaction without changing active context.
7. An interrupted pending tool becomes `unknown_outcome`; the first exact fingerprint replay is blocked with an explicit reconciliation signal.
8. Natural-language summaries remain auxiliary and never override checkpoint authority.

## Forbidden Actions
